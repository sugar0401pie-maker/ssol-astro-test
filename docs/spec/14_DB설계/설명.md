# 쏠 아스트로 하우스 — DB 테이블 설계 초안 v1 (2026-10-10)

schema.sql은 Supabase(PostgreSQL)용 초안이다. 문법 검사(파서)는 통과했고, 실제 프로젝트에 적용하기 전에 기존 디저트 테스트·쏘웰라 테이블 이름과 맞춰야 한다.

## 큰 구조

```
auth.users (임시 계정 = 익명 로그인 → 로그인하면 같은 id로 연결)
 ├─ 공용(쏘웰라와 공유) ─ consents · payments · sowella_passes · wellness_results · share_links · funnel_events
 └─ 점성술 전용 ─ astro_birth_profiles → astro_sessions → astro_chart_results
                                                 ├→ astro_free_results (무료 조립 기록)
                                                 ├→ astro_paid_reports (결제 후)
                                                 └→ astro_ai_calls (AI 호출·검증 기록)
```

## 테이블 한눈에

| 테이블 | 무엇 | 누가 읽나 |
| --- | --- | --- |
| consents | 화면 4 필수 동의 3개(버전 포함) | 본인 |
| payments | 토스 결제(1,900원) | 본인 |
| sowella_passes | 쏘웰라 3일 이용권 | 본인·쏘웰라 |
| wellness_results | 쏘웰라에 넘길 요약(handoff). 테스트마다 한 줄 | 본인·쏘웰라 |
| share_links | 공유 링크(무료 요약만) | 누구나(slug) |
| funnel_events | 퍼널 이벤트 | 서버·분석만 |
| astro_birth_profiles | 생년월일·시간·출생지·좌표·정확도 | 본인만(쏘웰라로 안 넘김) |
| astro_sessions | Q1~Q3 답, 진행 상태, 엔진·DB 버전 | 본인 |
| astro_chart_results | 엔진 계산 결과 JSON(재방문 때 재사용) | 본인 |
| astro_free_results | 무료 구간에 쓴 DB 행·표현 번호 | 본인 |
| astro_paid_reports | 유료 리포트 완성 문장, 섹션별 출처(ai / ai+b12 / db) | 본인 + 결제 완료 + 생성 완료 |
| astro_ai_calls | 모델·토큰·비용·검증 결과 | 서버만 |

## 꼭 지킬 것

- **결제 전 유료 본문은 클라이언트로 보내지 않는다.** RLS가 결제 전에는 astro_paid_reports 행을 아예 보여 주지 않는다. 블러 영역은 서버가 B13 가짜 문장으로 채운다(각 부분 앞 2줄만 실제 문장).
- **쓰기는 서버만.** 사용자 권한(anon key)으로는 읽기만 가능하고, 생성·수정은 서버 라우트(service role)에서 한다.
- **쏘웰라는 wellness_results만 읽는다.** 출생정보 테이블은 쏘웰라에 권한을 주지 않는다.
- **같은 사람 = 같은 문장.** astro_free_results.assembly에 쓴 DB 행 ID와 표현 번호를 저장해, 다시 열어도 같은 결과를 보여 주고 상담사 검수 때 어떤 문장이 나갔는지 추적한다.
- **버전 기록.** 세션마다 engine_version·db_version, 리포트마다 prompt_version을 남겨 DB나 프롬프트가 바뀌어도 이전 결과를 설명할 수 있게 한다.

## 정해야 할 것

1. 기존 디저트 테스트의 결제(토스)·로그인·동의 API와 테이블을 그대로 쓸지 — 쓰면 이 초안의 공용 테이블 대신 기존 테이블에 product_key·test_key 같은 칸만 더한다(개발 담당 확인)
2. ~~익명 계정 보관 기간~~ → 확정: 30일. 임시 계정으로 결제하면 회원가입 안내(B11 PAY_TEMP_NOTE·PAY_TEMP_BANNER)
3. 공유 링크 만료(초안: 무기한, 필요하면 expires_at 사용)
4. 쏘웰라가 다른 테스트 결과(디저트·해양생물·타로)도 함께 읽을지 — wellness_results 구조는 이미 여러 테스트를 담을 수 있다

## 로그인 수단 (2026-10-10 추가)

- 인트로: [카카오로 로그인하기] + [네이버로 로그인하기], 저장 후 로그인 화면: 카카오·네이버·이메일.
- Supabase 기본 제공 로그인에 카카오는 있지만 네이버는 없다. 네이버는 Supabase의 사용자 지정 OAuth2 공급자(식별자 예: `custom:naver`, 인증·토큰·사용자 정보 주소를 직접 입력)로 붙인다. 무료 요금제는 사용자 지정 공급자 3개까지, Pro부터 제한 없음. 네이버가 이메일을 주지 않는 계정도 있어 `email_optional` 설정을 켠다.
- 디저트 테스트에 이미 네이버 로그인이 있으면 그 방식을 그대로 쓴다. 확정(2026-10-10): 카카오·네이버·이메일은 각각 별도 계정(합치지 않음).
- 익명(임시) 계정에서 카카오·네이버로 로그인하면 같은 user id로 연결해 출생정보·결과·결제가 그대로 남게 한다.
