# AI 출력 검증기 사용법 (v1, 2026-10-10)

06 리포트 프롬프트의 규칙을 코드로 옮겼다. Python(validate_ai.py)과 JS(validateAi.mjs, Next.js 서버 라우트용)는 같은 규칙이다.

- 금지어는 11_해석DB/astro_db_v1.2.json 안의 C1을 읽는다(JS는 `setC1(db.dbs.C1.rows)`).
- `validatePart(출력, ctx)` → 섹션 전체 + 안의 `<잇기>` 블록을 검사. `validateBridge(문장, ctx)` → 4문장 잇기만 검사.
- `finalizePart(generate, ctx, DB문장만판, B12문장)` → 1회 재생성 → 잇기만 실패면 B12로 교체 → 섹션이 두 번 실패면 DB 문장만.
- 테스트: `python3 test_validate_ai.py` (06 프롬프트의 좋은 예 4개 통과, 나쁜 예 8개 탈락, 재생성·대체 흐름 2개).

| 검사 | 코드 | 어디 |
| --- | --- | --- |
| 4문장 · 150~320자 | BRIDGE_SENTENCES · BRIDGE_LENGTH | 잇기 |
| 바람 단어 · 날짜 토큰 · 질문으로 끝내지 않기 | BRIDGE_WISH · BRIDGE_DATE · BRIDGE_QUESTION | 잇기 |
| DB 판정 문장과 60% 이상 겹침 | BRIDGE_OVERLAP | 잇기 |
| 역풍인데 좋게 포장 | BRIDGE_HEAD_POSITIVE · HEAD_POSITIVE | 잇기·섹션 5 |
| 토큰 밖 숫자 · 없는 토큰 · 조사 토큰 형식 | DIGIT · TOKEN_UNKNOWN · TOKEN_JOSA | 공통 |
| 입력에 없는 행성·별자리('이번 달·한 달'은 제외) | NAME_NOT_IN_INPUT | 공통 |
| 판정 이름 한쪽만(괄호 이름 빠짐) | LABEL_SINGLE | 공통 |
| 경제적 여유에서 수입·수익 예측 | MONEY_PREDICT | 공통 |
| C1 금지어(단정·공포·건강·투자 등) | BAN_xxx | 공통 |
| 같은 어미 3문장 연속 · 한쪽 어미 65% 초과 | ENDING_RUN · ENDING_RATIO | 공통 |
| ** · 표 | MARKDOWN · TABLE | 공통 |
| 두괄식 첫 문장 · DB 문장 누락 · 3일 이용권 문장 | LEAD · DB_MISSING · SOWELLA_3DAY | 섹션 |

잇기 길이 기준은 06 프롬프트 좋은 예를 실제로 재 보고 150~320자로 맞췄다(프롬프트도 같이 고침).
