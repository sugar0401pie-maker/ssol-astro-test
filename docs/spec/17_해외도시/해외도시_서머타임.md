# 해외 출생도시 — 서머타임·시간대 처리 노트

- 대상: `해외도시_목록.json` / `.xlsx` (4,565개 도시, 시간대 330개, 2026년 서머타임 시행 도시 890개)
- 계산 기준: Python `zoneinfo` + IANA tzdata **2026c**. 연도 범위 1940–2026.
- 목록의 `dst_now`(Y/N), `dst_years`(시행 연도 구간) 열은 이 문서와 같은 방식으로 계산했다.

## 1. 원칙: 고정 오프셋 금지, 도시의 IANA 시간대로 UTC 변환

1. 사용자가 고른 도시의 `timezone`(예: `America/New_York`)과 현지 출생 날짜·시각으로 **서버에서** UTC를 계산한다.
2. "뉴욕 = UTC−5" 같은 **고정 오프셋을 쓰지 않는다.** 같은 도시라도 서머타임 여부와 과거 표준시 변경 때문에 날짜마다 오프셋이 다르다.
3. 사용 도구: Python `zoneinfo`(기준 구현, `city_search.to_utc`) / JS는 `luxon`의 `DateTime.fromISO(local, {zone})` 또는 `Temporal`. 브라우저 `Intl`은 표시용으로만 쓰고 역변환(현지→UTC)은 서버에서 한다.
4. tzdata는 해마다 바뀌므로(예: 파라과이 2024, 멕시코 2022) 서버 패키지(`tzdata`)를 주기적으로 갱신한다.
5. 저장: 입력 원본(현지 날짜·시각·도시 geoname_id·timezone) + 계산 결과(UTC, 적용 오프셋, dst 여부, 경고)를 함께 남긴다.

### ③ 서머타임 전환 시각: 없는 시각·두 번 있는 시각

**권장 규칙 (서버 구현 기준)**

| 상황 | 예 | 처리 | 정확도 |
|---|---|---|---|
| 봄 전환: 시계가 건너뛰어 **존재하지 않는 시각** (`gap`) | 2021-03-14 02:30 뉴욕 | 건너뛴 길이만큼 **앞으로 밀어** 해석(02:30 → 03:30 EDT). `zoneinfo` fold=0 결과와 같다. | B로 표시 |
| 가을 전환: **두 번 있는 시각** (`ambiguous`) | 2021-11-07 01:30 뉴욕 | 기본값 = **첫 번째 발생(fold=0, 서머타임 쪽, EDT)**. 화면에서 "서머타임 해제 전/후"를 고를 수 있게 하면 선택값으로 덮어씀(fold=1 = 두 번째, 표준시). 선택 없으면 B로 표시. | 선택 시 A, 기본값이면 B |

- 판정: 같은 현지 시각을 fold=0/1로 각각 계산해 오프셋이 다르면 경고. fold=0 오프셋 < fold=1 오프셋이면 `gap`, 반대면 `ambiguous` (`city_search.to_utc`가 그대로 구현).
- 출생시각 모름(시각 미입력) 사용자는 해당 없음. 시각 경계 1시간 차이로 상승궁·하우스가 바뀔 수 있다는 안내 문구를 리포트에 붙인다.
