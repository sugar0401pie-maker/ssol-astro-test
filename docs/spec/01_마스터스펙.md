# 쏠 점성술 하우스 — 마스터 스펙 v2

기준일 2026-10-07 · 작성 jen(쏠 웰니스 하우스 CSO) · 개발 전달용 최종본. 이 문서가 기획서(Claude Docs)보다 우선한다.

## 1. 개요

출생일·출생시간·출생지로 실제 출생차트를 계산하고, 지금의 고민 응답으로 해석의 초점을 맞춰 ‘연말–2027–5년’ 세 구간의 마음 가이드를 주는 테스트다. 날짜만 보는 별자리 운세와의 차이는 두 가지다. 하나, 달·상승궁·하우스까지 들어간 개인 차트. 둘, 같은 차트라도 지금 고민이 다르면 결과가 달라진다.

**결과물** (무료 1종 + 유료 3종)

| 파트 | 기간 | 담는 내용 | 톤 |
| --- | --- | --- | --- |
| [무료] 2026년, 나의 한 해 | 2026 | 분기별 회고, 올해의 전환점, Q2 공감 | 인정·공감 |
| 연말까지 조심하면 좋을 것 | 테스트일 ~ 2026.12.31 | 조심할 세 가지, 연말의 순풍, 월별 주의점 | 구체적·가벼움 |
| 2027을 맞는 나의 마음가짐 | 2027 한 해 | 한 해 키워드, 놓아줄 것 1·키울 것 1, 분기별 흐름 | 다짐·선언 |
| 앞으로 5년의 흐름 | 2027 ~ 2031 | 연도별 테마 1줄, 전환점 시기, 큰 성장 과제 | 서사·조망 |

**포지셔닝**: 예언이 아닌 자기성찰 웰니스 콘텐츠. 점성술은 학술적 근거가 없으므로 ‘삶을 돌아보는 언어’로 쓰고, 실천 제안은 쏠 웰니스 하우스 지식베이스(ACT·REBT·긍정심리 등)에 근거를 둔다. “별이 주는 질문, 심리학이 주는 답”이 한 줄 콘셉트다.

## 2. 입력 설계

입력은 4개, 1분 안에 끝난다. 출생시간을 모르면 시간대 선택지로 근사 계산하고, 정확도 등급을 결과에 표시한다.

| 입력 | 형식 | 비고 |
| --- | --- | --- |
| 닉네임 | 텍스트 | 디저트 테스트의 이름·성별·호칭 온보딩을 대신 |
| 생년월일 | 양력 날짜 선택 | 양력만 받는다(음력 미지원) |
| 출생시간 | 시:분 또는 시간대 | 아래 시간대 선택지 참고 |
| 출생지 | 한국 17개 시·도 드롭다운 / ‘한국이 아니에요’ 체크 시 전 세계 도시 검색 | 국내는 시·군 단위, 해외는 도시 단위 → 위도·경도·시간대 ID |

**시간대 선택지(출생시간 모를 때)**

새벽(00–06시) / 오전(06–12시) / 오후(12–18시) / 저녁(18–24시) / 태어난 시간을 잘 모르겠어요, 5개로 확정. 계산 기준·정확도는 6-1 ‘화면 4 입력 규칙’을 따른다. 구간 안에서 캐릭터가 바뀌면 후보 선택 화면에서 고르게 한다(무작위 선택 금지).

**변환 주의점**

- 시간대는 고정 오프셋이 아닌 IANA 시간대 ID(Asia/Seoul 등)로 처리해 과거 서머타임을 자동 반영한다. 한국은 1948–1960년 사이 여러 해와 1987–1988년에 서머타임을 시행했고, 1954–1961년에는 표준시가 UTC+8:30이었다(해당 연도 출생자는 최대 1시간 30분 차이).
- 지명 검색·좌표는 한국 시·도 대표 좌표 상수 + 해외는 GeoNames 도시 목록 자체 DB(좌표·시간대 ID 포함, 6-1 참고).
- 저장은 ‘현지 시각 + 시간대 ID + 변환된 UTC’ 3가지를 모두 남겨 나중에 재계산할 수 있게 한다.

## 3. 점성술 계산 엔진

엔진은 ‘출생차트 1회 계산 + 기간별 트랜짓 이벤트 추출’ 두 단계다. 모든 천문 계산은 서버에서 하고, AI는 계산을 하지 않고 결과 JSON만 해석한다(환각 방지).

### 3-1. 출생차트 산출 항목

| 항목 | 내용 | 테스트에서의 역할 |
| --- | --- | --- |
| 태양 | 사인·하우스 | 삶의 중심 동기, ‘나다움’ |
| 달 | 사인·하우스 | 감정 욕구, 안정감의 조건 |
| 상승궁(ASC)·MC | 사인·도수 | 세상을 대하는 방식, 커리어 방향 (A·B등급만) |
| 수성·금성·화성 | 사인·하우스 | 말하는 방식, 사랑·가치, 추진력 |
| 목성·토성 | 사인·하우스 | 성장의 문, 책임과 숙제 |
| 천왕성·해왕성·명왕성 | 하우스 | 세대 행성이므로 사인 해석은 쓰지 않음 |
| 4원소·3양태 분포 | 불·흙·공기·물 / 활동·고정·변통 비율 | 캐릭터 계열 결정 (6장) |
| 주요 애스펙트 | 합·충·삼합·사협·육합, 허용 오브 6°(태양·달 8°) | 내면의 긴장·재능 문장 |

- 하우스 시스템은 **홀사인(Whole Sign)** 으로 확정. 계산이 단순하고 고위도 출생자도 깨지지 않으며, 출생시간 오차에 덜 민감하다. 연구용으로는 플라시더스도 함께 저장.
- 조디악은 서양 점성술 표준인 트로피컬.

### 3-2. 트랜짓 이벤트 추출

하늘에 있는 행성이 내 출생차트의 행성·축과 각도를 이루는 시기를 추출한다. 기간별로 쓰는 행성이 다르다.

| 결과 파트 | 사용 행성 | 이유 |
| --- | --- | --- |
| 연말까지 | 화성·금성·수성·목성·토성, 금성·수성 역행 | 주~월 단위로 체감되는 주기 |
| 2027 | 목성·토성 + 일·월식 + 화성 역행 | 한 해 테마를 만드는 행성 |
| 5년(2027–2031) | 토성·천왕성·해왕성·명왕성 + 목성 하우스 이동 | 삶의 국면을 바꾸는 느린 행성 |

**이벤트 점수** = 행성 가중치 × 대상 가중치 × 각도 가중치 × 지속기간 보정. 예: 토성 3 × 태양 3 × 합 1.0 = 9점. 기간별 상위 3~5개만 해석에 쓴다. 가중치 초안은 표에 없는 별도 설정 파일로 두고, 파일럿 후 조정한다.

**나이 기반 마일스톤**(개인차는 엔진 계산): 토성 리턴(약 29–30세, 58–59세), 목성 리턴(12년마다), 천왕성 충(약 40–42세), 해왕성 스퀘어(약 40–41세), 키론 리턴(약 50세). 5년 안에 들어오면 ‘전환점’으로 표시한다.

### 3-3. 2026말–2031 하늘의 큰 흐름(모든 사용자 공통)

| 시기 | 하늘의 사건 | 공통 문구 방향 |
| --- | --- | --- |
| 2026 10–11월 | 금성 역행(천칭·전갈), 수성 역행(전갈) | 관계·돈 결정은 다시 보기, 지나간 인연 재평가 |
| 2026말–2027 초 | 화성 역행(사자·처녀) 시작 | 밀어붙이기보다 속도 조절 |
| 2026.7 – 2027 중반 | 목성 사자자리 | 자기표현·창작·즐거움의 확장 |
| 2026 – 2028 초 | 토성·해왕성 양자리(해왕성은 2039년까지) | 새 시작을 위한 기초 다지기 |
| 2026 – 2033 | 천왕성 쌍둥이자리 | 배움·정보·소통 방식의 변화 |
| 2027 하반 – 2028 | 목성 처녀자리 | 일상 루틴·건강 습관 정비 |
| 2028 – 2030 | 토성 황소자리 | 돈·몸·안정의 단단한 토대 만들기 |
| 2030 – 2031 | 토성 쌍둥이자리, 목성 사수자리 | 새 분야를 제대로 배우고 넓히기 |
| 전 기간 | 명왕성 물병자리(2043년까지) | 공동체·기술과 나의 관계 재구성 |

표의 시기는 월 단위 근사치이며, 서비스에선 태양력 정확 날짜를 엔진이 산출한다. 개인 결과는 이 공통 흐름이 ‘내 차트의 어느 하우스·행성을 건드리는지’로 달라진다.

### 3-4. 라이브러리 선택

| 선택지 | 언어 | 라이선스 | 평가 |
| --- | --- | --- | --- |
| Swiss Ephemeris (pyswisseph) | Python | AGPL 또는 유료 상용 라이선스 | 업계 표준 정밀도. 소스 비공개 서비스라면 상용 라이선스 구매 필요 |
| Kerykeion | Python | AGPL (Swiss Ephemeris 기반) | 차트·SVG까지 나오지만 라이선스 조건 동일 |
| astronomy-engine | JS/TS·Python | MIT | 무료·상용 가능, 행성 위치 충분히 정밀. ASC·홀사인 하우스는 직접 계산(공식 단순) |

**확정**: MVP는 astronomy-engine(MIT) + 홀사인 하우스를 Next.js 서버 라우트에서 계산. 플라시더스·고급 기법이 필요해지면 Swiss Ephemeris 상용 라이선스로 전환. 라이선스 조건은 도입 전 법무 확인 필요.

**Astro-Seek 등 외부 사이트 활용**: 결과를 긁어오는 방식은 쓰지 않는다. 공개 API가 없고, 약관 위반 소지가 있으며, 사용자 출생정보가 외부로 나가고, 차단되면 서비스가 멈춘다. 대신 개발 중 테스트 출생정보 20~30건을 양쪽에 넣어 행성 사인·ASC 일치 여부를 대조하는 검수 기준으로 쓴다(Astro-Seek 기본 하우스는 플라시더스이므로 대조 시 홀사인으로 바꿔 비교). 직접 계산이 부담되면 유료 점성술 API([Astrologer API](https://kerykeion.net/astrologer-api/guides/astrology-software-development))도 대안이다.

## 4. 고민 응답 설계

질문은 3개, 모두 하나만 고르는 객관식이다(30초 안팎). 자유서술과 점수형 문항은 없고, 점성술 결과를 어느 쪽으로 풀어 줄지만 정한다.

| 번호 | 질문 | 선택지 | 결과에서 하는 일 |
| --- | --- | --- | --- |
| Q1 | 주요 고민(요즘 제일 신경 쓰이는 부분) | 직업·커리어 / 진로·자기계발 / 연애 / 가족 / 교우·사회관계 / 재정·생활안정 (6) | 어느 하우스·행성을 먼저 읽을지, 연말 주의점의 초점 |
| Q2 | 당신에게 2026년을 한 단어로 정의하면? | 버텨 / 배움 / 변화 / 멈춤 / 성취 / 이별 / 고생 / 그만하자 / 시작 / 설렘 (10) | 리포트 첫 문단의 공감 톤, 올해 하늘 흐름과 대조 |
| Q3 | 2027년에 희망하는 것은? | 안정 / 도약 / 회복 / 사랑 / 좋은 사람들 / 여유 / 건강한 생활 / 경제적 여유 / 인정 / 나다움 (10) | 2027·5년 파트의 중심 질문: “바라는 것이 언제 열리는가” |

- Q3 10개는 최종 확정 전 초안이다(8-3 남은 결정).
- Q3의 ‘건강한 생활’은 루틴·습관 쪽으로만 답한다. 질병·몸 상태 예측은 하지 않는다(7-3).
- Q2가 ‘그만하자’·‘이별’·‘고생’이면 리포트 톤을 한 단계 더 부드럽게 하고, 결과 하단에 쏘웰라·전문 상담 연결 안내를 함께 보여준다(진행을 막지는 않음).

## 5. 결합 로직

차트는 ‘무슨 일이 일어나기 쉬운가’, 고민 응답은 ‘그중 무엇을 어떤 톤으로 말할가’를 정한다. 점수는 서버가 계산하고 AI는 문장만 쓴다.

```
출생정보 → 차트 계산(출생차트 + 트랜짓 점수) ─┐
                                              ├→ 결합(서버: Q1 영역 이벤트 ×1.5, Q3 바람 지원도) → DB 문장 조립 → AI 연결문(유료만) → 자동 검증 → 결과
고민 응답 Q1~Q3 → 응답 채점(영역·2026 단어·2027 바람) ─┘
```

두 입력은 따로 계산된 뒤 서버에서 합쳐지고, AI는 완성된 이벤트 목록을 문장으로만 바꾼다.

### 5-1. 고민 영역 → 하우스·행성 매핑

| 고민 영역 | 관련 하우스 | 관련 행성 |
| --- | --- | --- |
| 직업·커리어 | 10·6 | 토성, MC |
| 진로·자기계발 | 9·3 | 목성, 수성 |
| 연애 | 5·7 | 금성, 화성 |
| 가족 | 4 | 달 |
| 교우·사회관계 | 11·3 | 수성, 천왕성 |
| 재정·생활안정 | 2·8 | 금성, 토성 |

**관련도 가산**: 트랜짓 이벤트가 Q1 영역의 하우스·행성을 건드리면 ×1.5. 덕분에 같은 차트라도 “연애”를 고른 사람은 금성 역행이, “커리어”를 고른 사람은 토성 트랜짓이 먼저 나온다. 관련 이벤트가 없으면 “이 영역은 하늘이 조용한 때, 내가 속도를 정할 수 있는 시기”로 말한다.

### 5-2. 바라는 것(Q3)이 언제 열리는가

Q3의 바람마다 연결된 행성·하우스를 정해 두고, 2027–2031 연도별로 ‘바람 지원도’를 계산한다. 지원도 = 그 자리를 돕는 트랜짓(목성 통과, 삼합·육합) 점수 − 가로막는 트랜짓(토성·명왕성의 합·충·사협) 점수.

| Q3 바람 | 보는 자리 | 연결 역량(6-3) |
| --- | --- | --- |
| 안정 | 토성, 4H·2H | 믿기 |
| 도약 | 목성, 10H·MC, 화성 | 선 지키기 |
| 회복 | 달, 6H·12H | 회복하기 |
| 사랑 | 금성, 5H·7H | 기대기 |
| 좋은 사람들 | 11H·3H, 수성 | 말하기 |
| 여유 | 금성, 12H·5H | 회복하기 |
| 건강한 생활 | 6H·1H, 화성 | 선 지키기 |
| 경제적 여유 | 2H·8H, 금성·토성 | 믿기 |
| 인정 | 태양, 10H·MC | 말하기 |
| 나다움 | 태양·ASC, 1H | 선 지키기 |

**판정(연도별)**: 순풍(지원도 상위) / 보통 / 역풍(하위). 기준값은 파일럿으로 정한다. C등급(출생시간 모름)은 하우스를 빼고 행성만으로 판정하고, 그 사실을 문장에 밝힌다.

### 5-3. 솔직하게, 그러나 희망을 — 안내 원칙

바람과 하늘의 흐름이 엇갈려도 결과를 좋게 포장하지 않는다. 사실을 먼저 말하고, 그 다음에 ‘언제, 왜 나아지는지’를 근거와 함께 준다.

| 2027 판정 | 문장 구조 | 예시(Q3 = 안정) |
| --- | --- | --- |
| 순풍 | 지원의 근거 → 잡는 방법 → 주의할 점 하나 | “2027년은 목성이 내 4하우스를 지나 기반을 다지기 좋은 해예요. 다만 서두르면 무리하기 쉬운 때도 있어요.” |
| 보통 | 하늘이 밀어주지도 막지도 않음 → 내 선택이 결과를 좌우 → 작은 실천 | “큰 흐름은 조용한 해예요. 그만큼 스스로 쌓는 루틴이 그대로 결과가 돼요.” |
| 역풍 | 솔직한 사실 → 행성 근거 → 지금 할 수 있는 것(이론 기반) → 열리는 해와 그 이유 | “2027년에 안정을 바로 얻기는 쉬운 흐름이 아니에요. 토성이 내 달과 긴장하는 시기라 흔들림이 있을 수 있어요. 지금은 흔들리지 않는 것보다 흔들려도 돌아올 자리를 만드는 때예요. 2029년에는 목성이 내 4하우스에 들어와, 그동안 다져 둔 기반이 안정으로 이어지기 쉬워져요.” |

- 역풍이면 2028–2031 중 첫 순풍 연도를 찾아 “00년에는 … 가능해져요”로 쓴다. 연도와 이유는 서버가 정해 넘기고, AI는 바꾸지 않는다.
- 5년 안에 순풍이 없으면 없는 해를 만들지 않는다. “앞으로 5년은 하늘의 큰 도움보다 내가 쌓는 힘이 결과를 좌우하는 시기”로 말하고, 지원도가 가장 높은 해를 ‘가장 가까워지는 해’로 알려준다.
- 희망은 행성 근거와 실천에서만 나온다. “다 잘될 거예요” 같은 근거 없는 위로, “반드시” 같은 단정은 쓰지 않는다.

### 5-4. 파트별 조립 순서

0. **2026 회고(무료, DB만)**: Q2 공감 도입 → 올해의 전환점(특정 날짜 이벤트: 토성 리턴, 외행성 별자리 이동 등) → 분기별 표 → 접힌 근거.
1. **연말까지**: 기간 내 상위 이벤트 3개(Q1 가산) → 두괄식(어떻게 조심할지) → 조심할 세 가지(표 내용을 다른 말로 요약) → 연말의 순풍 → 월별 표 → 접힌 근거.
2. **2027 마음가짐**: Q3 바람의 2027 판정(5-3 문장 구조) + 목성·토성이 지나는 하우스 → 한 해 키워드, 변화의 중립적 설명(새 기회일 수 있음), 놓아줄 것 1·키울 것 1, 분기별 표, 접힌 근거.
3. **5년 흐름**: 연도별 최고점 외행성 이벤트 + 나이 마일스톤 + Q3 지원도 곡선 → ‘열리는 해’와 그 이유(월별 3~4문장), 역풍 해 솔직하게, 5년의 큰 그림, 연도별 표, 접힌 근거.
4. **별이 주는 질문과 웰니스 제안**: 두괄식 질문 → 왜 이 질문인지(앞의 흐름 + 타고난 기질, 3~4문장) → 성찰 질문 3개 → 작은 실천 3가지(캐릭터 역량 × Q1, 이론명 비노출) → 쏘웰라 3일 안내.

## 6. 결과 화면 구성

결과 화면은 관계성 테스트에서 정한 ‘스크롤하면 리포트가 이어지다 블러 → 결제’ 페이월 구조를 그대로 쓴다. 무료 구간은 1~3번(태어난 순간의 하늘, 캐릭터, 2026 회고)이고, 유료 섹션은 제목과 두괄식 첫 문장만 선명하고 본문은 블러다.

### 6-1. 화면 흐름

1. 인트로(디저트 테스트와 동일)
2. 환영·닉네임
3. 점성술 경험 확인 → (처음이면) 안내
4. 생년월일·태어난 시간·태어난 곳(한 화면)
5. “3가지 더” 질문 Q1~Q3 (차트 계산은 이 동안 백그라운드에서)
6. 로그인 분기: 로그인 상태면 바로 결과, 아니면 로그인·가입(카카오·네이버·이메일) 후 결과
7. (시간대 선택이면) 캐릭터 후보 선택 / (역량 동점이면) 역량 확인
8. 결과: 무료 구간 → 블러 → 결제 → 전체 리포트
9. 공유 시트

| 화면 | 큰 글씨 | 작은 글씨 | 입력·버튼 |
| --- | --- | --- | --- |
| 1. 인트로 | 디저트 테스트와 동일 | — | — |
| 2. 환영 | 쏠 점성술 하우스에 오신 당신을 환영합니다. | 당신을 뭐라고 불러드리면 될까요? | 닉네임 입력란 / [이렇게 불러주세요] |
| 3. 경험 확인 | {닉네임}님, 오늘은 어떤 고민을 가져오셨나요? 그보다, 점성술은 오늘이 처음이신지요? (두 문장 같은 크기) | — | [전에 본 적이 있어요] → 4 / [네, 처음이에요] → 3-1 |

| 6. 로그인 분기 | — | — | 로그인 상태 → 바로 7 / 비로그인 → 로그인·가입 후 7 |
| 7. 결과 | 결과 페이지(6-2) | — | — |

**화면 4 입력 규칙** (두 경로 모두 같은 화면, 생년월일·시간·출생지를 한 화면에서)

- 생년월일: 연도·월·일 드롭다운 3개, 표시는 1990-05-21 형식. 연도 1900~2026, 일은 고른 월·윤년에 맞게 개수가 바뀜. 아래에 “실제로 태어난 날짜 기준(자정 이후 출생이면 다음 날)” 안내.
- 태어난 시간: 시(00~23)·분(00~59) 드롭다운 2개.
- [정확한 시간을 몰라요] 체크 → 시·분이 사라지고 아래 5개 중 하나를 고름.

| --- | --- | --- | --- |
| 시·분 입력 | 입력값 | 입력값 | A: 상승궁·하우스 모두 사용 |

- B: 6시간 구간에서 캐릭터가 하나로 모이면 그대로, 갈리면 후보 2~3개 중에서 고르게 한다(모의실험상 ±3시간 동일 76%).

**태어난 곳 처리**

- 한국: 시·도별 대표 좌표(시청·도청 소재지)를 상수로 둔다. 같은 도 안의 경도 차이는 최대 1° 안팎이라 상승궁 오차가 작다. 시간대는 Asia/Seoul.
- 해외: GeoNames의 인구 1.5만 명 이상 도시 목록(cities15000, 약 2만 5천 개, CC BY 라이선스)을 우리 DB에 넣어 자체 검색한다. 도시마다 좌표와 시간대 ID가 들어 있어 별도 API·비용이 없고 사용자 입력이 외부로 나가지 않는다. 표시는 “도시, 국가”(예: Los Angeles, 미국), 한글·영문 검색 모두 지원(GeoNames 대체명 사용).
- 목록에 없는 작은 도시는 “가장 가까운 큰 도시를 골라주세요” 안내.

**기타**

- 닉네임은 디저트 테스트의 이름·성별·호칭 온보딩을 대신하고, 조사는 기존 받침 판정 함수를 쓴다.

### 6-3. 캐릭터(쏠 기존 20종 재사용)

태양 별자리(양자리 등)는 생일로 자동 표시하고, 캐릭터는 출생차트 전체를 관계성 테스트와 같은 기준(**가장 에너지가 필요한 역량 × 주로 쓰는 방식**)으로 분류한 20종 중 하나다. 그래서 같은 양자리라도 캐릭터는 사람마다 다르다.

| 역량 \\ 방식 | 다가가기 (불) | 맞춰주기 (물) | 거리두기 (공기) | 조율하기 (흙) | 대응 행성 |
| --- | --- | --- | --- | --- | --- |
| 기대기 (친밀감) | 수달 | 해달 | 물범 | 비버 | 달 |
| 믿기 (안정감) | 원앙 | 펭귄 | 왜가리 | 백조 | 토성 |
| 선 지키기 (경계) | 복어 | 소라게 | 거북 | 조개 | 화성 |
| 말하기 (표현) | 물개 | 돌고래 | 혹등고래 | 개구리 | 수성 |
| 회복하기 (갈등) | 문어 | 해파리 | 가오리 | 불가사리 | 금성 |

**행(역량) = 출생차트에서 가장 긴장을 많이 받는 행성.**

- 행성별 긴장 점수 = 화성·토성·천왕성·해왕성·명왕성과의 합·사협·충(감점) − 목성·금성과의 합·삼합·육합(가점). 오브 6°, 가까울수록 크게.
- 다섯 행성의 점수 분포가 서로 다르므로, 점수를 그대로 비교하지 않고 행성별 백분위로 바꿔 가장 낮은 행성을 고른다(모의 출생 데이터 3,000건으로 보정표를 미리 만듦).
- 행성의 자리 품위(도메인·디트리먼트)는 쓰지 않는다. 토성은 한 별자리에 2년 반씩 머물러, 품위를 넣으면 ‘1990년대 초 출생자는 ‘믿기’ 0%, 2005년생은 56%’처럼 출생년도가 캐릭터를 정해 버린다.
- 동점(1·2위 차이 3%p 미만, 약 17%)은 “요즘 더 가까운 쪽은?” 확인 화면에서 사용자가 고른다(무작위 금지).

**열(방식) = 출생차트 전체에서 가장 강한 원소.**

- 불 → 다가가기, 물 → 맞춰주기, 공기 → 거리두기, 흙 → 조율하기.
- 원소 점수: 태양·달 3점, 수성·금성·화성 2점, 목성·토성 1점. 동점(약 13%)이면 달의 원소, 그래도 같으면 태양의 원소.
- ‘가장 약한 행성이 있는 별자리의 원소’를 방식으로 쓰는 안도 시험했지만, 역량과 방식이 서로 묶여 캐릭터별 비율이 1.2%~9.0%로 크게 치우쳐 버렸다.
- 공기↔거리두기, 흙↔조율하기는 상담사 검토를 마쳤다(확정).

**유형화 검증(모의실험)**: 1965–2005년 무작위 출생 시각 5,000건을 실제 천문 계산(astronomy-engine)으로 돌린 결과다. 이상값은 캐릭터당 5%다.

| 기준 | 결과 | 판단 |
| --- | --- | --- |
| 캐릭터 20종 비율 | 최소 3.5%(백조) ~ 최대 5.9%(소라게) | 고르게 퍼짐, 채택 가능 |
| 역량 5개 | 15.8%~22.6% (믿기가 조금 적음) | 보정표 조정으로 더 맞출 수 있음 |
| 방식 4개 | 24.2%~25.8% | 거의 균등 |
| 출생년도 편중 | 5년 단위 코호트별 ‘믿기’ 11%~22% | 크게 문제없음(품위 제외 효과) |
| 출생시간 오차 | ±3시간 안 같은 캐릭터 76%, ±6시간 58% | 시간대 선택(B등급) 시 4명 중 1명은 후보 선택이 필요 |

- B·C등급은 구간 안에서 30분 간격으로 캐릭터를 계산해, 하나로 모이면 그대로, 갈리면 후보 2~3개를 “더 나 같은 캐릭터는?” 선택 화면으로 보여준다.
- 모의실험 코드는 엔진 프로토타입(8-2 1단계)에 그대로 재사용한다. 점수 규칙을 바꿀 때마다 다시 돌려 분포를 확인한다.

**관계성 테스트와의 차이·연결**

- 같은 캐릭터지만 근거가 다르다. 관계성 = 연인 관계에서의 응답, 점성술 = 출생차트. 결과에는 “양자리 · 별이 본 나는 펭귄”처럼 별자리와 캐릭터를 함께 표기한다.
- 두 테스트를 모두 한 회원에게는 “관계 속 나는 해달, 별이 본 나는 수달” 비교 화면을 보여주면 교차 유입에 쓸 수 있다.
- 히든 ‘바다의 노인’은 관계성 테스트 전용으로 두고 여기서는 쓰지 않는다.
- 친구 궁합(무료)은 관계성 테스트의 방식 × 방식 ‘고리’ 10가지를 연인이 아닌 일반 관계 표현으로 다듬어 재사용한다.
- 디자인은 쏠 로고 색(남색·크림)을 기준으로 밤하늘 느낌만 더한다.

### 6-4. 디자인 요약 (상세: 02_디자인가이드.md)

- 콘셉트: 쏠 로고(남색·크림) + 펄골드, ‘밤의 하늘’. 화면 배경은 미드나잇 → 네이비 그라데이션 + 옅은 별. 긴 리포트 본문은 크림색 상자 위 네이비 글자.
- 캐릭터: 관계성 테스트 20종을 밤하늘 아래 장면으로 새로 그린 일러스트(03_캐릭터이미지프롬프트.json). 결과 화면 2번 섹션과 차트 휠 가운데 얼굴 아이콘에 쓴다.
- 출생차트 휠: 결과 화면 맨 위. 별자리 고리 → 하우스 고리 → ASC·MC 축 → 행성 → 각도 선(상위 8개) → 가운데 캐릭터 얼굴. 누르면 DB 해석(태양·달·상승궁 무료, 나머지 첫 문장만).
- 시기별 표(모바일): 펼친 상태는 2열(시기 + {닉네임}님에게는/무엇을 조심할까/마음가짐/테마). ‘하늘에서 일어난 일’은 행마다 접어 두고 누르면 열림(이벤트·날짜 + 뜻 한 줄, DB). 접힌 근거는 섹션 맨 끝.
- 시기 단위: 한 해는 분기, 3개월 안팎은 월, 5년은 연. 특정 날짜의 전환점은 표가 아니라 본문 문단.
- 5년 타임라인: 점 5개를 별자리 선처럼 연결, 순풍 = 밝은 별, 역풍 = 흐린 별, 열리는 해만 펄골드 반짝임.

## 7. AI 리포트 생성

디저트 테스트 파이프라인(서버 조립 + AI 생성 + 자동 검증 후 1회 재생성)을 재사용한다. 달라지는 것은 AI에 주는 입력이 ‘유형 코드’가 아니라 ‘계산된 이벤트 목록’이라는 점이다.

### 7-1. 서버 조립 vs AI 작성

| 섹션 | 담당 | 이유 |
| --- | --- | --- |
| 차트 휠, 날짜 구간, 캐릭터명, 5년 타임라인 뼈대 | 서버 | 숫자·날짜는 AI가 만들면 틀린다 |
| 연말 주의점 문장, 2027 마음가짐, 5년 연도별 문장, 별이 주는 질문 | AI | 개인화된 말투가 필요 |

**숫자·날짜를 만드는 방법** — AI는 숫자를 ‘쓰지’ 않고 ‘자리만 남긴다’.

1. **엔진이 계산해 JSON으로 저장**: 트랜짓은 하루 간격으로 각도를 훑어 ‘오브 안에 들어오는 날·정확한 날·벗어나는 날’을 구하고(정확한 날은 이분법으로 시간 단위까지), 역행은 행성 속도의 부호가 바뀌는 날, 별자리 이동은 경도가 30° 경계를 넘는 날로 구한다. 역행 때문에 같은 각도가 여러 번 지나면 한 이벤트로 묶고 구간을 여러 개 갖게 한다.
2. **서버 포맷 함수가 글자로 바꾼다**: 날짜 구간(“11월 3일~24일”, 연도가 바뀌면 “2026년 12월~2027년 2월”), 연도(“2029년”), 한국어 조사(받침 판정)를 함수 하나로 통일. 날짜는 사용자 현지 시간대(기본 Asia/Seoul) 기준.
3. **AI에는 자리 표시(토큰)만 준다**: 입력에 `{{E1_기간}}`, `{{열리는해}}`, `{{캐릭터}}` 같은 토큰과 그 뜻만 넣고, AI는 토큰을 문장에 그대로 쓴다. 서버가 출력 뒤 실제 값으로 바꾼다.
4. **검증**: AI 출력에 토큰 밖의 숫자가 있으면 실패, 필수 토큰이 빠지거나 없는 토큰이 있어도 실패, 입력에 없는 행성·별자리 이름이 나오면 실패. 1회 재생성 후에도 실패하면 해당 파트는 DB 문장만으로 보여준다.
5. **화면 요소는 AI를 거치지 않는다**: 차트 휠·타임라인·캐릭터 일러스트는 프론트 컴포넌트가 같은 JSON을 바로 그린다. 그래서 화면의 날짜와 본문의 날짜가 어긋날 수 없다.
6. **저장·검수**: 계산 결과 JSON에 엔진 버전을 붙여 저장하고 재방문 때 재사용. 테스트 출생정보 20~30건은 Astro-Seek과 대조하고, 날짜 구간·서머타임·자정 전후 출생 같은 경계 사례는 자동 테스트로 둔다.

### 7-2. 프롬프트 입력(JSON)

```json
{
  "user": {"nickname": "지우", "accuracy": "A"},
  "chart": {"sun": "양자리/11H", "moon": "처녀자리/4H", "asc": "쌍둥이자리", "element": "불"},
  "character": {"name": "수달", "competency": "기대기", "style": "다가가기", "theories_internal": ["EFT", "대인관계치료"]},
  "answers": {"q1_domain": "직업·커리어", "q2_word_2026": "변화", "q3_wish_2027": "안정"},
  "events_eoy": [{"token": "E1_기간", "from": "2026-10-25", "to": "2026-11-14", "event": "수성 역행(6H)", "score": 8.1}],
  "wish_support": {"2027": "보통", "2028": "순풍", "2029": "순풍", "2030": "역풍", "2031": "보통"},
  "wish_reason": {"2028": "토성-달 삼분(6·11월), 목성 4H(~8월)"},
  "first_open_year": 2028,
  "events_5y": ["..."],
  "soft_tone": false
}
```

예시 값은 샘플 리포트(1996-04-01 10:17 경기)의 실제 계산값이다. 날짜는 엔진이 채우고 AI에는 토큰으로 넘긴다. theories_internal은 문장 재료로만 쓰고 화면에 표시하지 않는다.

### 7-3. 금지 표현과 검증

- **단정 금지**: “~하게 됩니다”, “반드시”, “크게 잃습니다”. “~하기 좋은 시기”, “~을 돌아볼 만한 때”로 쓴다.
- **도메인 금지**: 건강 진단·질병 예측, 투자·주식 매매 시점, 만남·이별·이혼 권유, 사고·죽음 언급.
- **공포 마케팅 금지**: “조심하라”는 행동 제안으로만 끝내고, 불운을 막는 유료 상품 판매로 연결하지 않는다.
- **근거 표기**: 실천 제안은 지식베이스 기법(ACT 가치 명료화, REBT 생각 논박, 긍정심리 강점 활용 등)에서 가져오되, 이론명은 화면 어디에도 표시하지 않는다(내부 데이터로만 보관). 점성술 문장과 심리학 문장을 섞어 주장하지 않는다.
- **자동 검증**: validate\_report에 금지어 목록, 입력에 없는 날짜·행성 등장 여부, 섹션 누락 검사를 추가. 실패 시 1회 재생성.

**솔직함과 희망(5-3 적용)**

- `wish_support`가 역풍이면 바람을 이루기 어렵다는 사실을 첫 문장에 쓴다. 좋게 바꿔 말하거나 흐리지 않는다.
- 이어서 “`first_open_year`년에는 `wish_reason` 때문에 가능해져요”를 쓴다. 연도·근거는 입력값 그대로, 없는 해를 만들지 않는다.
- 검증: 역풍 입력인데 본문에 ‘순조로운’·‘좋은 해’ 같은 표현이 있으면 재생성.

**웰니스 유형·이론 결합**

- 리포트의 실천 문장은 캐릭터의 역량에 연결된 쏠 지식베이스 이론에서 가져온다. 예: 믿기 → 스키마치료·인생함정접근, 기대기·회복하기 → EFT, 말하기 → 대인관계치료·DBT 스킬, 공통 → ACT·REBT·긍정심리. 최종 매핑은 관계성 테스트 base\_knowledge를 재사용한다.
- 역할 분리: 점성술은 ‘언제·어느 영역이 힘든가’, 캐릭터는 ‘나는 어떻게 반응하는 사람인가’, 이론은 ‘그럼 무엇을 해볼 수 있나’를 말한다.
- 학자 이름·전문용어는 본문에 쓰지 않는다(디저트·관계성 테스트 프롬프트 규칙과 동일).

### 7-4. 모델 구성(확정)

쏘웰라 채팅은 GPT-6 Luna, 유료 리포트는 GPT-6.1 Sol로 연말·2027·5년 세 파트를 동시 생성한다. 리포트 1건 약 100원, 대기 20~30초가 목표다.

| 용도 | 모델 | 호출 방식 | 건당 비용(추정) | 대기(추정) |
| --- | --- | --- | --- | --- |
| 무료 결과(휠·캐릭터·2026 회고) | 없음 — DB 문장 조립 | — | 0원 | 즉시 |
| 유료 리포트 | GPT-6.1 Sol | 연말·2027·5년 3개 호출 병렬, 스트리밍 | 약 100원 | 20~30초 |
| 쏘웰라 3일 채팅 | GPT-6 Luna | 메시지마다 | 메시지당 1원 미만 | 수 초 |

- 병렬 3파트는 같은 공통 프롬프트(시스템·KB·차트 JSON)를 앞에 두어 캐시 할인을 받고, 파트별 지시만 뒤에 붙인다.
- 파트마다 validate를 따로 돌려, 실패한 파트만 1회 재생성한다.
- 결제 직후 생성을 시작하고, 사용자가 무료 구간을 읽는 동안 아래 파트가 채워지게 한다.
- 비용·속도는 업계 가격 정리 사이트(2026.10) 기준 추정치다. 입력 7천·출력 5천 토큰, 재생성 20%, 1,400원/달러를 가정했다. 출시 전 오픈AI 공식 가격과 가상 사용자 10명 실측으로 확정한다([가격 출처](https://www.aipricing.guru/openai-pricing/)).

### 7-5. 문장은 DB 우선 — AI는 잇기만

무료 결과는 AI 호출 0회, 100% 미리 쓴 DB 문장으로 만든다. 유료 리포트도 DB 문장이 뼈대이고, AI는 조각을 잇는 연결문과 Q1~Q3에 맞춘 2~3문장만 쓴다(전체의 20~30%). 상담사가 모든 문장을 미리 검수할 수 있고, 같은 차트면 같은 해석이 나온다.

| 우선순위 | DB | 행 수 |
| --- | --- | --- |
| 1 | 별자리 기본 정보 / 태양·달·상승궁 × 별자리 | 12 / 36 |
| 1 | 캐릭터 20종 점성술판 + 역량 5·방식 4 설명 | 29 |
| 1 | 원소 4 × 강함/부족 | 8 |
| 1 | 트랜짓 문장(외행성·목성·토성 5 × 출생 대상 7 × 합/조화/긴장) | 105 |
| 1 | 목성·토성 하우스 통과 / 수성·금성·화성 역행 × 하우스 | 24 / 36 |
| 1 | 하늘의 공통 흐름 2026말~2031 | 약 10 |
| 1 | Q2 공감 도입문 / Q3 바람 × 순풍·보통·역풍 + ‘열리는 해’ | 10 / 40 |
| 1 | 웰니스 실천(역량 5 × 고민 영역 6, 기존 575개 실천 DB 연결) | 30 |
| 1 | 고정 문구(고지문·정확도 안내·용어 사전·상담 연결) | 약 15 |
| 2 | 수성·금성·화성 × 별자리 / 행성 × 하우스 / 주요 각도 / 나이 마일스톤 | 36 / 84 / 42 / 5 |

1순위 합계 약 345행(원고 7~9만 자). AI로 초안 → 상담사 검수 순서로 만든다. 목록·쓰임새는 개발 패키지 05\_DB목록.md.

### 7-6. 말투·문체 규칙 (확정)

디저트 테스트 심층 리포트 프롬프트의 말투 규칙을 가져오고, 점성술에 맞게 바꾼다. 전문은 개발 패키지 06\_리포트프롬프트\_점성술.md.

| 항목 | 규칙 |
| --- | --- |
| 어미 | 입니다체·해요체를 번갈아 쓴다. 같은 계열 3문장 연속 금지, 한쪽 65% 이하. “~이에요” 연속 금지 |
| 호칭 | 섹션 첫 문장·핵심 판정 문장은 “{닉네임}님”, 나머지는 주어 생략 또는 “당신” |
| 해석 | 근거(행성 흐름 토큰) → 기제(쉬운 말) → 장면(3문장 이상, “~할 수 있어요”로 열어 둠) |
| 과거 | 2026년 회고는 점성술 근거가 있으면 “~했을 거예요”도 허용. 어린 시절·가족사 추측은 금지 |
| 두괄식 | 유료 섹션은 결론 한 문장을 독립 문단으로 시작(블러 화면에서 미리보기) |
| 강조 | \*\* 금지. 나열·구분은 • 말머리, 표·타임라인은 화면 컴포넌트 |
| 이론 | AI 문장과 화면 어디에도 이론명·학자 이름을 쓰지 않음(내부 데이터로만 보관) |
| 프레이밍 | 실천 제안은 상담사 설계, 점성술은 나를 돌아보는 상징 언어. 상담사가 점성술 예측을 보증하는 표현 금지 |
| 점성술 전용 | 예측 단정·공포 마케팅 금지, 솔직하되 서버 근거로 희망(5-3), 건강·투자·이별 예측 금지, 숫자는 토큰만 |
| 채팅 안내 | “이 리포트와 함께 3일 동안 쏘웰라 이용권이 제공됩니다.” |

## 8. 윤리·고지와 다음 단계

### 8-1. 고지와 개인정보

- 결과 하단 고정 고지: “점성술은 과학적으로 검증된 예측 도구가 아니며, 이 결과는 자기 성찰을 위한 웰니스 콘텐츠입니다. 중요한 결정은 현실의 정보와 전문가의 도움을 함께 살펴주세요.”
- 출생일시·출생지는 민감한 개인정보다. 수집 목적·보관기간 동의를 받고, 비회원 결과는 일정 기간 후 삭제. 출생지는 도시명과 좌표만 저장하고 상세 주소는 받지 않는다.
- Q2에서 ‘그만하자’·‘이별’·‘고생’을 고르면 리포트 톤을 한 단계 부드럽게 하고 결과 하단에 쏘웰라·전문 상담 연결 안내를 함께 보여준다(4장).
